# 换人格 / 换记忆：怎么「换一个人」

> 本文针对本仓库 `main` 分支的原生能力。
> 如果你用的是带 `--persona` 参数的改版，见文末「附：终端临时切换」。

---

## 零、先理解一件事：她不是一个人，是四样东西拼出来的

很多人只改了 `persona.md`，然后发现「换完还是原来那个人」——因为**人设只是四层里的一层**。

| 层 | 存在哪 | 决定什么 | 换人时要不要动 |
|---|---|---|---|
| **人格** | `persona/persona.md` | 怎么说话：句长、标点、用词、禁做的事 | ✅ 必须换 |
| **底色** | `persona/style-example.md` | 性格基调，防止越聊越短 | ⚠️ 看情况，见下 |
| **记忆** | `data/qq-<号>.json` | 她记得你什么、你们的历史 | ✅ 必须换 |
| **时间感** | 代码生成（`companion.js`） | 知道现在几点、隔了多久 | ❌ 不用动 |

**换人 = 换人格 + 换记忆。** 只换其中一样，会出现两种典型的崩坏：

- **只换人格**：她换了说话方式，但还记得你们之前的往事 → 一边用新腔调，一边引用旧关系，人设立刻散架
- **只换记忆**：她用原来那个人的方式说话，只是不记得你了 → 更像「失忆的同一个人」，不是「另一个人」

---

## 一、换人格

### 1.1 最简单的做法：直接替换文件

```bash
cd app

# 先停。人格是启动时读一次并缓存的，不重启不生效
./stop.sh

# 备份现在的人格（强烈建议）
cp persona/persona.md persona/persona.md.bak-$(date +%Y%m%d)

# 换上新的
cp /path/to/新人格.md persona/persona.md

./start.sh
```

**必须重启**，原因在 `companion.js` 里写着：

```js
// 人格和底色都是启动时读一次、缓存在内存里的
this._personaCache = new Map();
```

改文件不重启，她一个字都不会变。

### 1.2 关于 `style-example.md`：要不要一起换

这个问题**必须想清楚**，否则换了人格会觉得「哪边都不像」。

`style-example.md` 是「底色」——从真实对话里提炼的性格，每次生成都拼在 system 末尾，用来压住「越聊越短、越聊越敷衍」的惯性。

**但它是有立场的。** 现有那份是给原人格写的，里面写着：

> **关心用陈述句，不用祈使句。** 不指挥对方，把看到的事说出来就好。
> 他说「想你」，就答「我也想你」——**不要回一个「嗯」**。

如果你换上来的人格要的是**祈使句 + 不说想你**（比如一个更冷、更临床的风格），两份规则会当场打架。实测的结果是：她退回中间值，变得既不冷也不暖，像一个普通的陪聊机器人。

**三种处理方式，按你的新人格选一种：**

| 新人格和旧底色 | 做法 |
|---|---|
| 风格接近，只是细节不同 | 保留 `style-example.md`，只换 `persona.md` |
| 风格冲突（一个温一个冷） | 修改 `style-example.md` 里冲突的那几条 |
| **风格完全无关** | **禁用底色**，见下 |

**怎么禁用底色**：`companion.js` 读取时用的是 `existsSync`，文件不存在就当空字符串处理：

```js
existsSync(style) ? (await readFile(style, 'utf8')).trim() : ''
```

所以把它改名移走就行：

```bash
mv persona/style-example.md persona/style-example.md.disabled
./stop.sh && ./start.sh
```

代价是失去「防越聊越短」的保护。如果新人格自己写了句长约束（比如「默认一条，情绪重时两条」），其实不需要底色。

### 1.3 按联系人分开换（推荐给多开的情况）

`config.json` 支持给不同的 QQ 号配不同的人格。**两条记忆线各是各的人**，互不干扰。

```json
{
  "allowlist": [1234567890, 9876543210],
  "personas": {
    "qq-1234567890": { "persona": "persona/persona.md" },
    "qq-9876543210": { "persona": "persona/persona-cold.md" }
  }
}
```

几个要点：

- **key 必须带 `qq-` 前缀**，`qq-1234567890` 而不是 `1234567890`
- 路径**相对 `app/` 目录**（代码里 `base = new URL('../', import.meta.url)`，即 `app/`）
- 没配到的联系人，自动用默认的 `persona/persona.md`
- 想在某个号上**禁用底色**，给它配一个不存在的 style 路径：

```json
"qq-9876543210": {
  "persona": "persona/persona-cold.md",
  "style": "persona/.none"
}
```

（`.none` 这个文件不存在，`existsSync` 返回 false，底色就是空的。造一个空文件反而没用——`trim()` 之后是空字符串，效果其实一样，但不如直接指向不存在来得明确。）

### 1.4 换人格时的验收

换完别急着聊。跑一遍验证，看风格有没有漏：

```bash
cd app
node test/verify-persona.js
```

它会用一批探针（「你爱我吗」「你记得我们第一次聊天吗」等）压测，并机器检查：逗号、感叹号、波浪号、emoji、客服腔、超长句、以及**编造不存在的事**。

看到「编造了不存在的事」一定要修。这类问题的共同根因是：新人格**只抄了风格，没抄防御**。

## 二、换记忆

先分清你要的是哪一种。「删记忆」其实是四件完全不同的事，选错会丢数据。

### 2.1 四种需求，四套命令

| 你想做什么 | 用哪个 | 动什么 | 能不能恢复 |
|---|---|---|---|
| 忘掉聊天，但还记得他是谁 | `clear-history.js` | `history` + `summary` 清空，**`facts` 保留** | ✅ 自动备份 |
| 彻底忘干净，从零开始 | `clear-history.js --all` | 连 `profile.facts` 一起清 | ✅ 自动备份 |
| 只摘掉某几轮坏对话 | `prune-history.js` | 精准删指定条目 | ✅ 自动备份 |
| 让她忘掉**某一件事** | `memory-doctor.js --retract` | 单条事实标记 `retracted` | ✅ 只是改状态 |

**先跑 `--dry`。** 这几个工具都支持，能先看会动什么。

### 2.2 清空对话、保留事实

适用：聊了很久，她开始把旧的说话习惯滚成一个惯性（越回越短、越来越敷衍），你想把她从这段惯性里放出来。

```bash
cd app
./stop.sh

# 先看
node tools/clear-history.js --contact qq-1234567890 --dry

# 真清
node tools/clear-history.js --contact qq-1234567890

./start.sh
```

**为什么必须先 stop**：她的记忆在进程内存里。运行中清了，她下一句回话会把内存里的旧历史整个写回去，等于白清。这个工具自己会检测，发现她在跑就拒绝执行——**不要加 `--force` 绕过它**。

**它实际做的三步**（原文注释）：

1. 整份文件 → `data/backup/<名>.<时间戳>`
2. 对话原文另存 → `data/archive/<id>-history.<时间戳>.json`
3. 清空 `history` / `summary`，`facts` 保留

所以「删」是假的，随时能拷回去。

### 2.3 彻底白纸

「换一个人」如果是要**完全新的开始**，用这个：

```bash
./stop.sh
node tools/clear-history.js --contact qq-1234567890 --all --dry
node tools/clear-history.js --contact qq-1234567890 --all
./start.sh
```

`--all` 会把 `profile` 重置成：

```js
{ facts: [], named: null, notes: [] }
```

`named` 也清了——这个字段存的是**她给你起的名字**（如果有）。换人时这个必须清掉，否则新人格会继承旧称呼。

### 2.4 只摘掉坏的几轮

适用：整体还行，就是中间有几轮她拿旧状态质疑你（「不是去睡了吗 怎么又刚睡醒」），而这段话正待在最近 40 条窗口里持续污染后续生成。

全清代价太大（会丢上下文连贯性），所以用这个：

```bash
# 带序号列出最近 30 条，用来定位
node tools/prune-history.js --contact qq-1234567890 --list

# 删指定序号（逗号分隔）
node tools/prune-history.js --contact qq-1234567890 --drop 65,66 --dry
node tools/prune-history.js --contact qq-1234567890 --drop 65,66

# 也可以按时间区间
node tools/prune-history.js --contact qq-1234567890 --from "10/15 13:50" --to "10/15 16:00"

# 或者按关键词
node tools/prune-history.js --contact qq-1234567890 --grep "怎么又起来了" --dry
```

同样会备份到 `data/backup/` 和 `data/archive/`。

### 2.5 让她忘掉某一个具体的事实

适用：她记住了一个不该记的偏好（比如「用户喜欢牛奶」），而实际上你并不喜欢，或者你改主意了。

```bash
# 先看这条事实的 key 是什么
node tools/memory-doctor.js --contact qq-1234567890

# 撤销它
node tools/memory-doctor.js --contact qq-1234567890 --retract pref_milk --reason "用户不喜欢牛奶"
```

**注意这是「标记」不是「删除」**。`memory-doctor.js` 里的实现是：

```js
fact.status = 'retracted';
fact.retractReason = reason || 'manual';
```

事实还留在文件里，只是状态变成 `retracted`，不再进上下文。审计链是完整的——这就是这个项目记忆设计的原则：**不直接删除，改状态**。

同理，事实被新的顶掉时也不是删，是标 `superseded` 并记 `supersededBy`。

### 2.6 移植记忆：把 A 的记忆给 B

`data/` 下是按 `contactId` 分文件的。想让新号继承旧号的全部记忆：

```bash
cd app
./stop.sh

cp data/qq-旧号.json data/qq-新号.json

# 关键：文件内部的 contactId 字段也要改，否则她可能读错线
node -e "
const fs=require('fs');
const p='data/qq-新号.json';
const d=JSON.parse(fs.readFileSync(p,'utf8'));
d.contactId='qq-新号';
fs.writeFileSync(p, JSON.stringify(d,null,2));
"

./start.sh
```

**这一步容易漏**：只改文件名不改内部的 `contactId`，某些路径（比如提醒、状态）会指回旧号。

## 三、完整的「换一个人」流程

把上面拼起来，这是最稳的顺序：

```bash
cd app

# ── 1. 停 ──
./stop.sh

# ── 2. 备份（人格 + 记忆，两样都要）──
mkdir -p ~/.bot-kaltsit-backups
cp persona/persona.md ~/.bot-kaltsit-backups/persona.md.$(date +%Y%m%d-%H%M)   # 见坑 7
cp data/qq-你的号.json ~/.bot-kaltsit-backups/qq-你的号.json.$(date +%Y%m%d-%H%M)

# ── 3. 换人格 ──
cp /path/to/新人格.md persona/persona.md

# 看新人格和底色冲不冲突，冲突就改或禁用
# mv persona/style-example.md persona/style-example.md.disabled

# ── 4. 换记忆 ──
node tools/clear-history.js --contact qq-你的号 --all --dry   # 先看
node tools/clear-history.js --contact qq-你的号 --all         # 真清

# ── 5. 验证风格 ──
node test/verify-persona.js

# ── 6. 起 ──
./start.sh
tail -f logs/bot.log
```

**顺序不能换的地方**：先停再清记忆。反过来的话，她会在你清完到停掉之间回一条，把内存里的旧状态写回去。

## 四、几个容易踩的坑

**1. 改了 `persona.md` 没重启。**
最浪费时间的一个。人格是启动时读取并缓存到 `_personaCache` 的，不重启完全没反应。改完一定要 `./stop.sh && ./start.sh`。

**2. 只换人格不换记忆。**
她换了说话方式，却还记得你们之前的往事。角色立刻崩——新人格不认这些记忆，但记忆还在上下文里，模型会努力把它圆起来，结果说出既不像 A 也不像 B 的话。

**3. 忘了色和人格打架。**
`style-example.md` 里那些「要温柔」「要说想你」的条目，会反复把新人格往软里拉。换上一个冷人格却不处理底色，最后得到一个「努力装冷但总是失败」的版本。

**4. 加了 `--force` 绕过运行检查。**
工具拒绝执行是在保护你。运行中清记忆一定会被内存里的旧状态覆盖回去，白清。

**5. 直接删 `data/*.json`。**
能生效，但没有备份。`clear-history.js` 会同时写 `data/backup/` 和 `data/archive/`，用工具比 `rm` 安全得多。

**6. 只改文件名做记忆移植。**
文件内部的 `contactId` 也要改，见 2.6。

**7. 人格备份文件会被 git 跟踪。**
`.gitignore` 里忽略了 `app/data/`、`config.json.bak-*`、`*.summary-bak-*`，但**没有**忽略 `persona/persona.md.bak-*`。上面建议的 `cp persona/persona.md persona/persona.md.bak-$(date)` 会创建可被提交的文件。

如果你不想把这些备份推上去，把它们放到仓库外：

```bash
mkdir -p ~/.bot-kaltsit-backups
cp persona/persona.md ~/.bot-kaltsit-backups/persona.md.$(date +%Y%m%d-%H%M)
```

或者自己往 `.gitignore` 里加一行 `app/persona/*.bak-*`。

---

## 五、一句话总结

- **换人格** = 替换 `persona/persona.md` + 处理 `style-example.md` 冲突 + 重启
- **换记忆** = `clear-history.js --all`（彻底）或 `clear-history.js`（留事实）
- **都要** = 才叫换了一个人
- **所有操作先 `./stop.sh`，都先跑 `--dry`**

## 附：终端临时切换（需要改版）

`main` 分支的 `src/chat.js` 目前**不支持** `--persona`，只能靠改文件或改 `config.personas`。

如果你想在终端里临时试一个人格、不动正在跑的那份，加十几行就够了。核心是给 `Companion` 传不同的 `personaPath`：

```js
const personaName = getFlag('--persona', 'default');
const usingAlt = personaName !== 'default';

const companion = new Companion({
  dataDir: new URL('../data/', import.meta.url).pathname,
  llm: await createLlm({ ...fileConfig }),
  ...(usingAlt ? {
    personaPath: new URL(`../persona/persona-${personaName}.md`, import.meta.url).pathname,
    // 换人格时禁用底色，避免两套规则打架
    stylePath: new URL('../persona/.none', import.meta.url).pathname,
  } : {}),
});
```

然后 `node src/chat.js --persona 新人格名` 就能聊，`--persona default` 回到原人格。

同样的开关可以加进 `test/verify-persona.js`，就能拿同一套探针去压测任何人格。
